Overview

This is a sandbox for designing and testing heuristic evaluation functions for depth-limited minimax search, using checkers as a test case. These functions allow the algorithm to make an educated guess about how the game is going for a player. Using the panels to the left, the user can decide how different factors contribute to this guess.

This tool allows users to practice a core computer science skill: taking something they understand intuitively (e.g., how to evaluate a position in checkers) and making it precise enough for a computer to use.

How It Works

Evaluation Functions

An evaluation function takes a board position and returns a single number — higher is better for the side to move. The minimax algorithm simulates different ways the game could play out over a fixed number of future turns (determined by its depth limit) and uses its evaluation function to score the resulting board positions. Using these scores (and the assumption that both players are trying to maximize their own advantage), minimax selects whichever action seems best.

Unfortunately, there are simply too many different ways a game could play out from start to finish, so a shallow depth limit is often the only practical option. This means that the algorithm will usually have to rely on the guesses supplied by its evaluation function instead of actual outcomes (i.e., win, lose, or draw). For this reason, the quality of these guesses is critical to success.

To see how minimax explores different ways a game could go, see this visualization.

The Weighted Feature Sum

Each evaluation function here is a weighted sum of board features — pieces, kings, mobility, and so on. Every feature carries a weight: a positive weight rewards it, a negative weight penalizes it. "Player" features describe the player's side; "Enemy" features describe the opponent's side. Designing a function means choosing which features matter and by how much. Explanations of each feature can be found in the "How To" tab.

Test and Play

You define two functions, EF1 and EF2. The "Test" tab plays many games between them in parallel and charts the win / draw / loss proportions as they accumulate — a fast way to tell whether a change actually helped. The "Play" tab runs a single game you can watch or join: assign each color to a function or to yourself, and follow it move by move.

Reading the Score

On the "Play" tab, the EF(state) readout beside each agent shows its score of the current position (from its own side) and how that score changed on the last move. Pause and nudge a weight to watch the score respond — a concrete illustration of how your formula judges a position. Evaluation functions cannot be edited during a game unless it is first paused.

A Note on Weights

The relative sizes of the weights are what encode a value system. A weight set larger than the weight on one's pieces tends to backfire. Minimax will trade away pieces to chase it, and an advantage on a single feature is rarely worth such a sacrifice. Start with small weights and tweak them up and down. Keeping feature weights small lets them break ties between otherwise equal positions without overwhelming other features.

Test Controls

Start / Pause
Begins a new run of games. Click again to pause. Click once more to resume.
Stop
Ends the current run, leaving its results on screen.
N Games
How many games to play in a run.
Random Rollouts
Opens each game with 1-2 random moves per side. Increases diversity of games sampled — essential when agents are deterministic.
Cores
How many games run in parallel, one per worker thread. Increasing cores will shorten runs but reduce performance on other tasks.

Play Controls

Red / Black
Assigns each side to EF1, EF2, or User (you). Red moves first.
Play / Play Again / Pause / Resume
Play/Play Again starts a new game. Pause halts it and unlocks evaluation functions for editing; Resume continues with changes applied.
Step
Plays exactly one move, then pauses. Agent-vs-agent games only.
Reset
Stops current game and returns board to opening position.
Move Speed
How long a piece takes to slide to its destination.
Turn Gap
The pause between one move and the next.
Moving a piece (User)
Click a glowing piece to select it, then click a highlighted square to move there; jumps preview their full path. When a capture is available, only capturing moves are offered.

EF Controls

Depth
How many moves ahead the search looks. Deeper play is stronger but slower.
Quiescence
Extra search past the depth limit that waits (up to this many moves) for pieces to be out of danger. Helps prevent search from stopping in the middle of an exchange.
Player / Enemy Pieces
The number of pieces each side has, including both men and kings.
Player / Enemy Kings
The number of kings each side has.
Player / Enemy Vanguard
Pieces in the half of the board nearest the opponent.
Player / Enemy At Risk
Pieces the opponent could capture on the next move.
Player / Enemy Mobility
How freely each side can move, summed per piece as the fraction of its possible moves that are open. A man has 2 possible moves, a king 4; so a king with 3 open scores 0.75.
Player / Enemy Back Row
Pieces still on their own back row. These are the squares the opponent must reach to make a king.
